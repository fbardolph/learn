Cross-entropy loss

You’ll compute the one number every language model is trained to push down, see where it comes from, and see why it’s the same thing as file size.

One prediction, one bill

Show a model “The cat sat on the” and it doesn’t answer with a word. It answers with a probability for every token it knows. Then the real text reveals what came next, and the model gets a bill:

$$\text{loss} = -\ln p(\text{the token that actually came next})$$

That’s the surprise from Lesson 2, in nats (natural log) because that’s what training code uses. Put 0.9 on the right token and you pay $0.105$ nats. Put 0.1 on it and you pay $2.30$.

Notice what the bill ignores. It doesn’t matter how the model split the rest of its probability among the wrong tokens. Only the probability on the truth counts.

The model has given its probabilities and the real next token is revealed. Which numbers does the loss for this step use?

The loss is $-\ln p$ of the actual token, nothing else. The other probabilities matter only indirectly: they all add up to 1, so any probability spent on wrong tokens is probability not spent on the right one.

The model gave the actual next token probability $0.25$. What’s the loss in nats? (Use $\ln 4 \approx 1.386$.)

$-\ln 0.25 = -\ln \tfrac14$.

The log of a reciprocal is minus the log: $\ln \tfrac14 = -\ln 4$.

So $-\ln \tfrac14 = \ln 4 \approx 1.386$ nats. In bits it’s $-\log_2 \tfrac14 = 2$, and $1.386 \times 1.443 \approx 2$ checks out.

Where the probabilities come from: softmax

Inside, the model first produces one raw score per token, called a logit. Logits can be any number, negative or positive. To turn them into probabilities:

  1. Raise $e$ to each logit: $e^{z}$. Now everything is positive, and a bigger logit gives a much bigger number.
  2. Divide each by the total, so they add up to 1.

That’s softmax. Worked example with five candidate tokens:

Three tokens have logits $1$, $0$ and $0$. What probability does softmax give the first one? (Use $e \approx 2.718$.)

Exponentiate: $e^1 = 2.718$, $e^0 = 1$, $e^0 = 1$.

Total: $2.718 + 1 + 1 = 4.718$.

First token: $2.718 \div 4.718 = 0.576$.

The nudge is simple. For the true token, the logit goes up by $(1 - p)$: a lot if the model gave it little probability, hardly at all if it was already confident. Every other token’s logit goes down by its own probability, so the tokens that stole the most get pushed down the most. (Where that rule comes from is calculus, which the Calculus leaf will reach.)

Try one more thing: drag every logit up by the same amount. The probabilities don’t change, because softmax only cares about the gaps between logits.

Averaged over real text: cross-entropy

Training doesn’t look at one prediction. It averages the loss over every position in a huge pile of text. If the text really comes from some true distribution $p$ and the model predicts $q$, that average settles at

$$H(p, q) = \sum p \,(-\log q),$$

the cross-entropy: how often each outcome really happens, times what the model pays when it does.

Back to the weather from Lesson 2. The truth is sun $\tfrac12$, cloud $\tfrac14$, rain $\tfrac14$, so the entropy is $1.5$ bits. In bits:

Cross-entropy is never below the entropy. The best a model can do is predict the true probabilities, and then it pays exactly the entropy. Any gap is bits wasted by a wrong model. (That gap has a name you’ll meet in papers: the KL divergence.)

Wherever you set the truth, the curve’s lowest point sits right at $q = p$, touching the dashed entropy floor.

Training loss = average surprise on real text = cross-entropy. It can’t go below the text’s entropy, and it reaches it only when the model’s probabilities match reality.

A coin is fair, but the model predicts heads $\tfrac34$, tails $\tfrac14$. What’s the cross-entropy in bits? (Use $-\log_2 \tfrac34 \approx 0.415$.)

Heads happens half the time and costs $-\log_2 \tfrac34 \approx 0.415$ bits.

Tails happens half the time and costs $-\log_2 \tfrac14 = 2$ bits.

$H(p,q) = \tfrac12(0.415) + \tfrac12(2) = 0.2075 + 1 = 1.2075 \approx 1.21$ bits. The entropy of a fair coin is 1 bit, so the overconfident model wastes about 0.21 bits per toss.

As the probability on the truth heads to 0, the loss heads to infinity. One confident mistake (0.0001 on the truth) costs as much as about 900 confident hits at 0.99. So a model trained on this loss learns to hedge: when it genuinely doesn’t know, it spreads probability rather than betting everything on one answer.

Model A always gives the right token probability 0.6. Model B gives it 0.99 nine times out of ten, but 0.0001 the tenth time. Which has the lower average loss?

A: $-\ln 0.6 = 0.511$ nats every time.

B: $0.9 \times (-\ln 0.99) + 0.1 \times (-\ln 0.0001) = 0.9 \times 0.010 + 0.1 \times 9.21 = 0.009 + 0.921 = 0.930$ nats.

B’s rare confident blunder costs more than all its confident hits save.

From loss to file size

Lesson 3 showed that an arithmetic coder spends the model’s surprise in bits. So the training loss is a compression rate: bits (or nats) per token. To get the size of a whole document, do it in two steps:

  1. Rate × length. Average loss per token × number of tokens = total.
  2. Convert units. Nats × 1.443 = bits. Bits ÷ 8 = bytes.

Example: 1,000 tokens at 2.0 nats per token is $1000 \times 2.0 = 2000$ nats. Then $2000 \times 1.443 = 2886$ bits, and $2886 \div 8 \approx 361$ bytes for the whole document.

A common slip is to skip step 1: $2.0 \times 1.443 \div 8 = 0.36$ is bytes per token, not the size of the document.

A document is 2,000 tokens long. The model’s average loss on it is 0.8 bits per token. How many bytes does the whole document compress to?

Step 1, rate × length: $2000 \times 0.8 = 1600$ bits in total.

Step 2, convert: $1600 \div 8 = 200$ bytes.

(If you got 0.1, that’s $0.8 \div 8$: the bytes for one token.)

Perplexity: loss as a number of choices

Papers often report perplexity instead of loss. It undoes the log: $e^{\text{loss}}$ for nats, or $2^{\text{loss}}$ for bits.

Why bother? Because it reads as “how many equally likely options the model is choosing among”. A loss of $\ln 4 = 1.386$ nats gives perplexity $e^{1.386} = 4$: on average the model is as unsure as if it were picking uniformly from 4 tokens. Lowering perplexity from 20 to 10 means the model has halved its effective uncertainty.

A model’s loss is 3 bits per token. What’s its perplexity?

For bits, perplexity is $2^{\text{loss}} = 2^3 = 8$. The model is as unsure as a uniform pick among 8 tokens.

Check

You add 5 to every one of a model’s logits. What happens to its probabilities?

Each $e^{z}$ gets multiplied by the same $e^5$, and so does the total. The factor cancels when you divide: $\dfrac{e^{z_i + 5}}{\sum e^{z_j + 5}} = \dfrac{e^5 e^{z_i}}{e^5 \sum e^{z_j}} = \dfrac{e^{z_i}}{\sum e^{z_j}}$.

Why can’t a language model’s loss on real text ever reach 0?

A loss of 0 means probability 1 on every actual token: total certainty about what comes next. Real text contains genuinely unpredictable things, so its entropy is above 0, and cross-entropy is never below entropy.

A training run reports a loss of 2.2 nats per token. What is that in bits per token? (1 nat ≈ 1.443 bits.)

$2.2 \times 1.443 = 3.17$ bits per token. Same quantity, different unit: like converting miles to kilometres.

In your own words: why is training a model to lower its cross-entropy loss the same as training it to be a better compressor?

The loss is the model’s average surprise, $-\log p$, on the token that actually came next. Plugged into an arithmetic coder, the model spends exactly that surprise per token (Lesson 3). So average loss is the compressed size per token, and pushing the loss down shrinks the file. The floor for both is the entropy of the text.
